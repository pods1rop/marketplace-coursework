# Тестирование под нагрузкой и сквозной сценарий

## Нагрузочное тестирование (Apache JMeter 5.6)

План `marketplace.jmx` содержит четыре сценария, которые выполняются последовательно:

| Сценарий    | Пользователей | Итераций | Назначение                         |
|-------------|---------------|----------|------------------------------------|
| Smoke       | 1             | 10       | Базовая проверка работоспособности |
| Load        | 5             | 20       | Типичная дневная нагрузка          |
| Multithread | 20            | 50       | Пиковая нагрузка в час продаж      |
| Stress      | 50            | 100      | Стресс-оценка запаса прочности     |

Каждая итерация — шесть запросов: `GET /auth` (получение CSRF-токена), `POST /auth/login`,
`GET /catalog?categoryId=…`, `GET /product/{id}`, `POST /cart/add/{id}`, `GET /orders`.
Между запросами — случайная пауза 100–300 мс. Учётные записи берутся из `users.csv`
(50 пользователей `jmeter_user1…50` с паролем `password123`; их нужно один раз зарегистрировать на сайте).

`generate_jmx.py` генерирует план под диапазоны id категорий и товаров конкретной базы:

```
python generate_jmx.py marketplace.jmx "14,18" "13,30"
```

Запуск (приложение уже работает на `localhost:8080`):

```
jmeter -n -t marketplace.jmx -Jusers=users.csv -l results/run.jtl
```

Перед измерением стоит сделать один прогревочный прогон и отключить SQL-трассировку:
`--logging.level.org.hibernate.SQL=WARN --logging.level.org.hibernate.orm.jdbc.bind=WARN`.

### Результаты (AMD Ryzen 5 3500, 32 ГБ, Windows 10, MySQL 8.0)

| Сценарий    | Среднее, мс | 90-й перцентиль, мс | Запросов/с | Ошибки |
|-------------|-------------|---------------------|------------|--------|
| Smoke       | 28,9        | 78                  | 4,4        | 0 %    |
| Load        | 27,6        | 77                  | 19,3       | 0 %    |
| Multithread | 36,5        | 84                  | 73,7       | 0 %    |
| Stress      | 114,4       | 258                 | 142,5      | 0 %    |

Всего 36 660 запросов без ошибок. Подробности по эндпоинтам — `results/summary.json`, графики — `results/*.png`.

## Сквозной сценарий

`e2e_check.sh` проходит основные сценарии всех ролей через HTTP с настоящими CSRF-токенами
(61 проверка): заявка на роль продавца, модерация с причиной отклонения, запрет доступа к чужим товарам и заказам,
корзина, отзывы, жизненный цикл заказа, уведомления, предупреждения, блокировка, смена роли, отчёт.

```
DB_PASSWORD=... bash e2e_check.sh
```

Скрипт создаёт тестовых пользователей `sellerNNNN` / `buyerNNNN` и товары от их имени.
